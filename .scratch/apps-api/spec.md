# Spec: apps/api — Foundation + Catalog + BOW Documents Vertical Slice

Status: ready-for-agent

## Problem Statement

As the EdukSource PH owner, I have a Turborepo monorepo scaffold, a working Studio AI pipeline on Node (Fly.io) that can extract a BOW PDF to structured objectives JSON, and docs that describe a full marketplace (store, admin, api, studio, docs) — but I have no deployed `api` Worker to own Postgres writes. Studio currently caches extractions only in-memory per-file, so an editor who re-uploads the same BOW days later pays the full extraction cost again. The catalog (products, product versions, previews) and the durable BOW Document index (`bow_documents`) defined in ADR-0007/0008 exist only on paper — there are no Drizzle tables, no migrations, no `packages/db` or `packages/schemas`, and `apps/api` is an empty placeholder (`AGENTS.md` + `CONTEXT.md` only). Without `api`'s `/internal/*` endpoints, Studio cannot persist generation metadata or extraction identity, and `admin` cannot trigger or review a production-derived draft. The modular monolith boundaries in `docs/specs/2026-08-19-api-modular-monolith-design.md` are also unenforced, so Phase 2 logic risks landing as tangled cross-module imports that will be expensive to untangle later.

## Solution

Ship a deployable `apps/api` foundation that proves the entire `api`-is-sole-DB-gatekeeper path (ADR-0003) end-to-end on Cloudflare Workers, scoped to the only slice that has a real consumer today: **Catalog + BOW Documents**.

Create the two shared packages that the rest of the roadmap depends on — `packages/db` (Drizzle schema + `postgres-js` client, owned exclusively by `api`) and `packages/schemas` (shared Zod contracts, consumed via `@hono/zod-openapi`) — wire Workers (`wrangler.jsonc`, `compatibility_date`, `DATABASE_URI` + `INTERNAL_SERVICE_TOKEN` vars, stub auth middleware), enforce module boundaries via Biome `noRestrictedImports`, and deliver five OpenAPI-annotated endpoints backed by real Postgres writes/reads:

- `GET /products` (filtered), `GET /products/:id`, `POST /internal/products` (service-token, creates draft `product` + `product_versions` with `source: studio_generated`)
- `GET /internal/bow-documents/:contentHash`, `POST /internal/bow-documents` (service-token, ADR-0007 durable index, ADR-0008 normalized-text hash identity)

This establishes the gatekeeper, the migration history, the OpenAPI contract, and the Studio→R2→`api` durable-cache flow (Studio uploads bytes to R2, `api` stores only keys) — the seam every later phase (admin UI checkpoint, cart/orders, Search events) will reuse. Everything else (store, admin, payments, email, full 8-module surface, R2 reads, event bus) remains explicitly deferred.

## User Stories

1. As an editor, I want to call `GET /internal/bow-documents/:contentHash` before extracting, so that a re-uploaded BOW that normalizes to the same text hash hits the durable cache and skips re-extraction.
2. As an editor, I want `POST /internal/bow-documents` to persist `contentHash` + `gradeLevel` + `learningArea` + `schoolYear` + `r2JsonKey`/`r2PdfKey` + `extractionProvider`/`extractionModel`, so that Studio's producer-side normalized-text hash becomes the durable Extraction identity.
3. As Studio (internal caller), I want `POST /internal/bow-documents` to reject duplicate `contentHash` with a conflict error, so that concurrent first-extractions don't create duplicate durable records.
4. As Studio, I want both internal routes to require `X-Internal-Token: <INTERNAL_SERVICE_TOKEN>` and reject missing/invalid tokens with 401, so that the durable index is not writable from the public internet.
5. As an editor, I want `POST /internal/products` to create a draft `product` + `product_versions` (`source: studio_generated`, `studioJobId` nullable) in one transactional call, so that generated slides/docs/exams are reviewable before publishing.
6. As an editor, I want `GET /products` filtered by `gradeLevel`/`subject`/`term`/`strand`/`topic`/`status` with pagination, so that I can browse the catalog by the same BOW facets Studio extracts.
7. As a shopper (future), I want `GET /products` to return only `published` products by default while admin sees `draft` too (via role), so that unpublished Studio drafts never leak to the storefront.
8. As a shopper, I want `GET /products/:id` to return a single product with its current `product_versions` preview metadata, so that the store detail page has one fetch.
9. As an admin, I want `GET /products/:id` to return 404 with a stable `{ error: { code, message } }` shape when the product does not exist, so that the UI can render a not-found state without parsing free-text.
10. As an editor, I want `GET /internal/bow-documents/:contentHash` to return the stored `r2JsonKey`/`r2PdfKey` without `api` proxying R2 bytes, so that the R2-for-bytes / Postgres-for-index split in ADR-0007 is honored.
11. As the owner, I want `schoolYear` to be required on `POST /internal/bow-documents`, so that the catalog safety-net check in ADR-0008 (`gradeLevel`+`learningArea`+`schoolYear` near-duplicate prompt) has a real key to query.
12. As the owner, I want `contentHash` validated as a 64-char hex string at both Zod and DB level, so that a byte-hash vs normalized-text hash misuse is caught before persistence.
13. As Studio, I want any validation failure on `POST /internal/*` to return 422 with Zod issue details, so that pipeline errors are debuggable without tailing Workers logs.
14. As an operator, I want `GET /health` (or `GET /`) to return 200 without touching Postgres, so that Cloudflare health checks don't count as DB load.
15. As an operator, I want `DATABASE_URI` and `INTERNAL_SERVICE_TOKEN` validated on Worker boot (Zod env, min 32 chars for token), so that a misconfigured `wrangler.jsonc`/`dev.vars` fails fast with a clear message.
16. As a developer, I want `packages/db/src/schema/index.ts` to be the single `drizzle-kit` source and single migration history, so that `drizzle-kit generate`/`migrate` produce one linear migration set.
17. As a developer, I want `packages/schemas` to export `CreateProduct`, `ProductFilters`, `CreateBowDocument`, and `BowDocumentParams` as Zod schemas, so that `api`'s `@hono/zod-openapi` stubs and future `store`/`admin` share the same contract without drift.
18. As a developer, I want any cross-module import of `**/modules/*/service.ts` to fail `pnpm lint` via Biome `noRestrictedImports`, so that the cheapest-possible-enforcement catches the "just this once" service leak under deadline pressure.
19. As a developer, I want `app.ts` to mount `routes.ts` (session) and `internal-routes.ts` (service-token) via separate middleware (`requireSession` stub vs `requireInternalToken`), so that the two auth regimes in spec §3 Rule 6 never mix in one file.
20. As a developer, I want cross-module calls to go through `port.ts` (single input object, single return value, RPC-shaped) and only via `index.ts` barrels, so that a later microservices extraction is a `port.ts` implementation swap, not a call-site rewrite.
21. As a developer, I want Drizzle access restricted so only a module's own `service.ts` touches its tables (`catalog` touches `products`/`product_versions`/`product_previews`, `bow-documents` touches `bow_documents`), with a deliberate exception for explicit cross-module joins only when reviewed, so that spec §3 Rule 1 is visible in code review.
22. As a developer, I want the Postgres driver to be `postgres` (`postgres-js`) with per-request `createDb(c.env.DATABASE_URI)` (not a top-level singleton), so that the Worker runtime (`workerd`) has no Node `pg` compat issues and `DATABASE_URI` comes from `c.env` vars.
23. As a developer, I want `turbo run build | check-types | lint | test` to pass with the new packages wired into `pnpm-workspace.yaml` `packages/*`, so that the monorepo tasks compose without a custom pipeline.
24. As a developer, I want `vitest` tests for this slice to exercise `app.request()` (Hono in-memory) against a real Supabase Postgres branch, covering middleware, Zod validation, and Drizzle writes, so that `POST /internal/*` is proven DB-backed without pulling `workerd`/`miniflare` into the first PR.
25. As the owner, I want the durable-cache flow to remain: Studio computes the normalized-text hash → `GET /internal/bow-documents/:hash` → on miss uploads JSON+PDF to R2 via S3 API → `POST /internal/bow-documents` with keys, so that the cost/latency win of ADR-0007/0008 is realized without `api` ever holding Postgres credentials in Studio.

## Implementation Decisions

- **Scope (Q1=C):** foundation + one vertical slice — `catalog` + `bow-documents` — because Studio's durable extraction cache is the only internal consumer that exists today; the remaining six modules (`cart`, `orders`, `checkout`, `licenses`, `coupons`, `reviews`, `feedback`) are explicitly deferred to later phases and no stub files for them are created in this slice.
- **Database host (Q2=A):** use the existing Supabase Postgres via `DATABASE_URI` already in `.env`; do not introduce a local Postgres `docker compose` dual-env story in this slice; avoid Supabase-specific features (Auth, Storage, RLS-as-primary) per ADR-0004 so the Drizzle abstraction keeps the migration path swappable.
- **Auth (Q3=A):** stub `shared/middleware/auth.ts` — `requireSession` attaches a mock `c.get('user')` (role-aware) and `requireRole('admin'|'editor')` is enforced on session routes, but no real BetterAuth verification; `internal-routes.ts` uses `requireInternalToken` (separate middleware) so the two auth regimes never mix. Defer BetterAuth tables (`users`/`sessions`/`accounts`) until auth becomes real — `packages/db/src/schema/users.ts` is not created in this slice.
- **Schema ownership (Q4=A):** create `packages/db` now (canonical per spec §2 and ADR-0010) — `src/schema/products.ts` (covers `products`, `product_versions`, `product_previews`), `src/schema/bow-documents.ts` (owns `bow_documents`), `src/schema/index.ts` as the combined `drizzle-kit` source, plus `src/client.ts` `createDb` and `drizzle.config.ts`; `apps/api` imports `@eduksource/db` and never owns its own `drizzle.config.ts`.
- **Contract location (Q5=A, Q10=A):** create `packages/schemas` narrow — `src/catalog.ts` and `src/bow-documents.ts` only — and use `@hono/zod-openapi` in `api` so `GET /openapi.json` is served from day one; stubs live directly in `modules/catalog/routes.ts` and `modules/bow-documents/internal-routes.ts` per spec §7 (no separate API-first exercise to reconcile later).
- **Runtime (Q6=A):** `apps/api` runs as `Hono` on Cloudflare Workers via `wrangler.jsonc` (`compatibility_date: 2026-08-24`, `compatibility_flags: ["nodejs_compat"]` only if needed for `postgres-js`), no extra Node host; `vars` are `DATABASE_URI` + `INTERNAL_SERVICE_TOKEN`; local dev uses `.dev.vars` (gitignored) with `.dev.vars.example` placeholder; `pnpm dev --filter=@eduksource/api` is `wrangler dev --port 8787`; do not add an `env.staging` namespace until Phase 8.
- **Catalog schema (Q7=A, Q17 B-with-term):** `products` with `id` (serial/uuid), `slug` unique, `title`, `description` nullable, `gradeLevel`, `subject`, `term` (not `quarter` — align to BOW document language per ADR-0006), `status` `draft|published|archived`, `createdAt`/`updatedAt`; `product_versions` with `productId` FK, `version` int, `source` `manual|studio_generated`, `studioJobId` nullable, `r2Key`, `createdAt`; `bow_documents` with `contentHash` PK (64 hex), `gradeLevel`, `learningArea`, `schoolYear` NOT NULL, `r2JsonKey`, `r2PdfKey`, `extractionProvider`, `extractionModel`, `extractedAt`; R2 holds bytes, Postgres holds only the lightweight index row per ADR-0007 (no inline `jsonb`); `strand`/`topic` are filter fields in `ProductFilters`/API, not necessarily separate columns in this migration — they may filter via `product_versions` or preview metadata and can be promoted to columns later without a breaking change.
- **Service token (Q8=A, Q16=B):** single env `INTERNAL_SERVICE_TOKEN` (≥32 bytes, e.g. `openssl rand -hex 32`), header `X-Internal-Token`, middleware `requireInternalToken` in `shared/middleware/auth.ts`; you supply the secret (not generated or logged), scaffolding includes `.dev.vars.example` and `apps/studio/.env.example` placeholders; `studio` and future `search` share the same token per `architecture.md §4`.
- **R2 binding (Q9=A):** no R2 binding in this slice; `bow-documents` service validates/stores `r2JsonKey`/`r2PdfKey` strings only and returns them as-is; `api` never reads R2 bytes, never presigns, never proxies — keeps the sole-DB-gatekeeper property clean and avoids `miniflare` R2 mock until the admin browse/reuse feature needs it (post-Phase 5).
- **OpenAPI surface (Q10=A):** exactly five endpoints are DB-backed in this slice — `GET /products`, `GET /products/:id` (public/session), `POST /internal/products`, `GET /internal/bow-documents/:contentHash`, `POST /internal/bow-documents` (service-token); public `POST /products` (admin+editor) is deferred to Phase 5 admin CRUD; stubs return real Drizzle results, not `zod-mock`.
- **Boundary enforcement (Q11=A):** Biome `noRestrictedImports` denylist for `**/modules/*/service.ts` and `**/modules/*/internal-routes.ts` in `apps/api/biome.json` (or `packages/config/src/biome/base.json` override), documented in `apps/api/AGENTS.md`; the stronger "only `index.ts`" and "own tables only" remain convention + code review per spec §4.
- **Drizzle client (Q12=A):** `packages/db/src/client.ts` exports `createDb(connectionString)` using `drizzle-orm/postgres-js` + `postgres(connectionString, { prepare: false })`; `app.ts` middleware does `c.set('db', createDb(c.env.DATABASE_URI))`; services receive `db` via function args, never import `createDb` directly.
- **Migrations (Q13=A):** `packages/db/drizzle.config.ts` with `schema: "./src/schema/index.ts"`, `out: "./drizzle"`, `dialect: "postgresql"`, `dbCredentials: { url: process.env.DATABASE_URI }`; `pnpm --filter @eduksource/db db:generate` / `db:migrate` via `drizzle-kit` run locally/CI against Supabase; Workers never runs migrations at runtime.
- **Errors + logger (Q14=A):** `packages/logger` stays Node-only for Studio; `apps/api/src/shared/logger.ts` is a thin `console.log` JSON wrapper (Workers tail-friendly); `src/shared/errors.ts` owns `AppError` (status via `http-status`, `code`, `message`) and `errorHandler` middleware that renders `{ error: { code, message, details? } }`; no `pino` on Workers, no `nodejs_compat` for logging alone.
- **Testing (Q15=A):** `vitest` Node pool for `service.ts` where needed, but primary seam is Hono `app.request()` (in-memory, no `workerd`) against a real Supabase test DB/branch; this exercises `requireInternalToken`, Zod validation, and `bow_documents` uniqueness without `vitest-pool-workers`/`miniflare`; promote to `workerd` pool only when checkout webhooks need Workers binding simulation.
- **Env validation (Q19=A):** `apps/api/src/config/env.ts` Zod-validates `DATABASE_URI` (postgres://) + `INTERNAL_SERVICE_TOKEN` (min 32) + `LOG_LEVEL` on boot; missing/invalid throws with a clear message before `createDb`.
- **Route mounting (Q18=A):** `src/app.ts` mounts at root as spec writes — `app.route('/', catalog.routes)`, `app.route('/', catalog.internalRoutes)`, `app.route('/', bowDocuments.internalRoutes)` — no `/api` prefix; Cloudflare route `api.eduksource.ph/*` provides namespacing if needed.

## Testing Decisions

- **What makes a good test:** test external HTTP behavior at the highest seam (`app.request()`), not `service.ts` internals or Drizzle mock wiring. Assert status, response JSON shape, error codes, and Postgres side-effects (row exists after `POST`, conflict on duplicate `contentHash`, 401 without `X-Internal-Token`, 422 on invalid Zod body, 404 on missing product). Do not assert how `createDb` is called, how `postgres()` is instantiated, or the exact SQL string — those are implementation details.
- **Seams chosen (highest possible, fewest):**
  - **Preferred (1 seam):** `app.request()` HTTP boundary — the Worker entrypoint (`src/index.ts` → `src/app.ts`) is the single external seam. All catalog and bow-documents tests go through it, which implicitly covers middleware (`requireSession` stub, `requireInternalToken`), `zValidator`/`@hono/zod-openapi`, and `service.ts` via real `postgres-js` + Supabase. This is the existing prior art seam: `apps/studio` already tests routes via `app.request()` + `vi.mock('../lib/ai/providers.js')` (see `apps/studio/src/routes/extract.test.ts`, `health.test.ts`).
  - **Inner seam only if needed:** `service.ts` unit with an injected `db` double for pure business-logic branches (e.g., hash normalization, slug collision) — kept minimal because `app.request()` already provides the DB-backed proof for `POST /internal/*`, the whole point of the vertical slice. No new broker or event seams are introduced; the in-process event bus (`shared/events/bus.ts`) is Phase 10 per spec §5 and is not built.
  - **Confirmed:** HTTP seam matches prior art and your expectation that `pnpm test` runs without `workerd` in this slice (Q15=A).
- **Modules under test:** `modules/catalog` (`routes.ts` + `internal-routes.ts` + `service.ts` + `port.ts` via callers) and `modules/bow-documents` (`internal-routes.ts` + `service.ts`); plus `shared/middleware/auth.ts` (`requireInternalToken` 401 paths) and `shared/errors.ts` (404/409/422 mapping). `shared/events/bus.ts` is out of scope.
- **Prior art reused:** Turborepo `pnpm test` → `vitest run` with `transit` + `@eduksource/config#build` dependency (per `turbo.json`); `packages/config/src/vitest/base-config.ts` base config; `apps/studio` coverage shape (`vitest.config.ts`, `coverage/blob`) — no new test harness is invented.
- **Integration data:** tests run against a real Supabase Postgres branch/schema (same `DATABASE_URI`, not mocks) with per-test truncation in `beforeEach`; local `db:migrate` must be run once before the suite. Failure mode: if Supabase is unreachable in CI, integration tests are skipped with a clear diagnostic rather than passing silently.

## Out of Scope

- `apps/store`, `apps/admin`, `apps/docs`, `apps/search` — no code, no routes, no Tanstack Start wiring.
- Remaining `api` modules — `cart`, `orders`, `checkout` (PayMongo/Stripe), `licenses`, `coupons`, `reviews`, `feedback` — no `routes.ts`/`service.ts`/`port.ts` stubs; no domain events or `events.ts` files.
- Real BetterAuth (`packages/auth`), `users`/`sessions`/`accounts` tables, shared session cookie, role persistence beyond the stub middleware.
- R2 I/O in `api` — no binding, no `@aws-sdk/client-s3`, no presigning, no `GET` proxying of extraction JSON; `api` stores/returns keys only (ADR-0007 intact).
- Cloudflare Queues, watermarking, preview generation, email (Resend/`packages/email`), queues/webhooks, PayMongo/Stripe (ADR-0005), Turnstile, Sentry, PostHog/Plausible, NameCheap→Cloudflare DNS, SEO, privacy/terms, and the `search` RabbitMQ/gRPC microservices vehicle (ADR-0009) and `extraction` BOW Parsing gRPC (ADR-0011 parked).
- In-process event bus (`shared/events/bus.ts`) and any `events.ts` per-module files — Phase 10 seam per spec §5.
- `env.staging` wrangler environment, preview-deploy per-branch, staging Worker instance.
- `workerd`/`miniflare`/`vitest-pool-workers` for `api` — deferred until Workers binding simulation is actually needed.

## Further Notes

- **Spec lineage:** this spec is the grilled synthesis of the 19 decisions captured across four frontier rounds (Q1–Q19) late Aug 2026; it supersedes the raw grilling transcript as the source of truth. Decisions reference Q-numbers so a later reader can trace why `term` beat `quarter`, why `X-Internal-Token` exists, and why `postgres-js` was chosen over `pg`.
- **Vocabulary:** uses `CONTEXT-MAP.md` + `apps/api/CONTEXT.md` terms strictly — `Module`, `Port`, `Internal route`, `Domain event`, `BOW Document`, `Extraction identity`, `Provider registry` — never `Service`/`Extraction service`/`docling` as catch-alls (see per-context `Avoid` lines).
- **ADRs respected:** ADR-0001 (Workers vs Node split, Fly.io `sin`), ADR-0003 (api sole gatekeeper, Studio uploads to R2 via S3, calls `POST /internal/products`), ADR-0004 (Supabase temporary, Drizzle swappability, no Supabase Auth/Storage/RLS), ADR-0007/0008 (durable `bow_documents`, `contentHash` = normalized-text SHA-256, `schoolYear` required, `R2` for bytes), ADR-0009 (search seam deferred), ADR-0010 (per-package docs locality, tsconfig dedup), ADR-0011 (BOW Parsing parked — `unpdf`/`pdfjs-dist`+vision stays primary, no `EXTRACTION_SERVICE_TOKEN` in this slice).
- **Follow-up seam:** when Phase 5 lands `admin`'s checkpoint (`workflows/material-pipeline.md`), `POST /internal/products` will be called by `admin` instead of Studio directly, and `port.ts` (`getProductForCheckout`, `validateCoupon`, `grantLicense`) will become the real cross-module call sites to prove. Those will reuse the same HTTP + Port seams established here.
- **Secret handling:** `INTERNAL_SERVICE_TOKEN` is never committed, never logged, never printed by diagnostics; `.dev.vars.example` and `apps/studio/.env.example` contain only placeholders and validation messages point to the missing var name, not its value.
